# Источники новостей, лицензии и публикация в Google Play

Актуальность заметки: **15 августа 2026 года**.

Этот документ — технический и продуктовый чек-лист, а не юридическое
заключение. Условия API и правила Google Play могут измениться. Перед каждой
публикацией нужно повторно открыть ссылки из раздела
[«Официальные документы»](#официальные-документы), проверить изменения и
обновить дату выше.

## 1. Принятое решение по сборкам

| Источник | `debug` | `release` | Назначение |
|---|---:|---:|---|
| NewsData.io | Да | Да | Основная новостная лента и поиск |
| GDELT | Да | Да | Международные события, источники и поиск по глобальной повестке |
| News API | Да | **Нет** | Уже реализованный источник только для разработки и демонстрации архитектуры |
| The Guardian | Нет | Нет | Не используется из-за дополнительных лицензионных требований |

Отсутствие рекламы, подписок и покупок **не превращает публичное приложение в
development-среду**. Версия из Google Play является production-версией.

### Что обязательно обеспечить на уровне сборки

- В `release` не должно быть рабочего API-ключа News API.
- `release` не должен выполнять запросы к `newsapi.org` ни при каких настройках
  пользователя или ошибках конфигурации.
- News API желательно подключить через `src/debug` или debug-only binding Hilt.
  Если общий интерфейс остаётся в `main`, release-реализация не должна содержать
  ключ и сетевой клиент News API.
- Список доступных источников в UI должен зависеть от варианта сборки:
  `NewsData.io + GDELT` для release и дополнительно `News API` для debug.
- Добавить тест, проверяющий, что в release-конфигурации нет доступного значения
  `NEWS_API` и запросов к домену `newsapi.org`.
- Не полагаться только на скрытие ключа через `local.properties`: значение из
  `BuildConfig` попадает в APK и может быть извлечено. Для ключа NewsData.io
  желательно использовать собственный минимальный backend/proxy с лимитами,
  если правила тарифа разрешают такой способ доступа.

## 2. News API: только debug

Бесплатный Developer plan разрешён только для разработки и тестирования в
development-среде. Он запрещён в staging и production, в том числе во
внутреннем production. Это ограничение действует и для бесплатного приложения
без рекламы.

Правила проекта:

- не включать News API в Google Play release;
- не показывать News API в настройках release-версии;
- не добавлять News API key в release secrets CI/CD;
- не использовать полученные через News API данные в скриншотах Google Play,
  если нет уверенности в правах на конкретные тексты и изображения;
- не загружать полный текст оригинальных статей самостоятельно: условия News
  API отдельно запрещают использовать сервис для републикации защищённого
  авторским правом материала;
- при изменении тарифов не включать News API в release автоматически — сначала
  повторно проверить условия production-использования.

## 3. NewsData.io: основной release-источник

Публичные материалы NewsData.io указывают, что Free plan разрешено использовать
для коммерческих проектов. Следовательно, бесплатное portfolio-приложение без
монетизации в принципе подходит. На бесплатном тарифе доступны ограниченные
поля и отсутствует полный текст статьи.

### Разрешённая модель отображения

В приложении следует показывать только поля, фактически возвращённые API и
разрешённые текущим тарифом:

- заголовок;
- краткое описание/сниппет;
- имя оригинального издателя;
- автора, если он предоставлен;
- дату и время публикации;
- категорию и язык;
- ссылку на оригинальную публикацию;
- изображение только после подтверждения, что текущие условия разрешают его
  публичное отображение в стороннем приложении.

Полный текст нельзя получать скрейпингом страницы издателя. Кнопка
«Читать в источнике» должна открывать оригинальный URL в браузере или Custom
Tabs.

### Атрибуция NewsData.io

На каждой карточке и экране статьи нужно явно показывать оригинального
издателя. На экране «Источники и лицензии» нужно указать:

- что приложение получает агрегированные данные через NewsData.io;
- ссылку на NewsData.io;
- ссылку на актуальные Terms and Conditions;
- что права на оригинальные статьи и медиа принадлежат соответствующим
  издателям/правообладателям;
- что приложение не является автором и издателем этих материалов.

### Что подтвердить у NewsData.io до релиза

Публичное разрешение коммерческого использования не отвечает автоматически на
все вопросы о конкретных полях. Нужно написать в поддержку и сохранить ответ в
проектных записях вне репозитория. В запросе перечислить точный сценарий:

> Free, ad-free Android portfolio app published on Google Play. The app displays
> the title, description, source, author, publication date, original link and,
> if permitted, image URL returned by the API. Is public display and persistent
> caching of these fields, including favorites, allowed on the Free plan?

Нужно отдельно получить подтверждение для:

- публичного отображения `image_url`;
- длительного хранения заголовка и описания в Room;
- сохранения данных в «Избранном»;
- проксирования запросов через собственный backend;
- обязательной формулировки атрибуции, если она существует.

Пока письменного подтверждения нет, безопасный режим такой:

- хранить минимум метаданных;
- не сохранять полный текст;
- использовать собственные placeholder-изображения;
- всегда показывать издателя и ссылку на оригинал;
- предусмотреть очистку устаревшего кэша.

## 4. GDELT: данные разрешены, контент издателей — нет

GDELT разрешает неограниченное и бесплатное академическое, коммерческое и
государственное использование собственных наборов данных. Разрешены также их
перераспространение и публикация при условии указания GDELT и ссылки на проект.

Это разрешение относится к **данным GDELT**, а не ко всем материалам, которые
GDELT обнаружил на сайтах СМИ.

### Что можно использовать

- идентификаторы и данные событий GDELT;
- даты, страны, темы, категории и аналитические признаки;
- домен и название источника;
- URL оригинальной публикации;
- результаты поиска и связи между событиями;
- собственные производные представления этих метаданных;
- заголовок только как атрибутированную часть ссылки на оригинальный источник,
  без создания впечатления, что статья опубликована приложением.

В интерфейсе и на экране «Источники и лицензии» добавить текстовую атрибуцию:

> Event and news metadata provided by the GDELT Project — gdeltproject.org.

Текст должен содержать кликабельную ссылку на `https://www.gdeltproject.org/`.

### Картинки из GDELT

Поля вроде `socialimage`, `sharingimage` или URL изображения обычно указывают на
файл стороннего издателя. Открытая лицензия GDELT не означает, что GDELT может
передать приложению авторские права на эту фотографию.

Правило для release:

- **не отображать, не скачивать, не кэшировать и не проксировать изображения,
  найденные GDELT на сайтах издателей**, если для конкретного файла нет явной
  лицензии, разрешающей такое использование;
- не использовать такие изображения в иконке, feature graphic, скриншотах и
  других материалах Google Play;
- не считать hotlink безопасной заменой лицензии;
- не брать логотипы СМИ для карточек без разрешения правообладателя;
- для GDELT-карточек использовать собственные иллюстрации/placeholder либо
  лицензированные изображения с корректной атрибуцией.

Допустимые варианты изображений:

- собственные ресурсы приложения;
- собственные AI-generated иллюстрации, для которых условия используемого
  инструмента разрешают публикацию;
- public domain/CC0;
- Wikimedia Commons, только после проверки лицензии конкретного файла и
  добавления требуемой атрибуции;
- материал издателя, только если есть явное письменное разрешение или лицензия.

Лицензию, автора и URL каждого стороннего разрешённого изображения нужно
хранить вместе с данными об изображении, чтобы UI мог показать атрибуцию.

### Текст статей из результатов GDELT

- Не загружать и не републиковать полный текст страницы издателя.
- Не генерировать локальную «копию статьи» из HTML оригинального сайта.
- Не переводить и не пересказывать статью как собственную публикацию без
  отдельного анализа прав на такой сценарий.
- Показывать метаданные и открывать оригинальную страницу через Custom Tabs.
- Явно указывать оригинального издателя рядом с заголовком.

## 5. Общая модель карточки и экрана статьи

Подробная UI/UX-спецификация, навигация и решение использовать Custom Tabs
зафиксированы в
[article_details_screen_notes.md](article_details_screen_notes.md).

Для каждого элемента ленты модель должна позволять показать:

- `provider`: NewsData.io или GDELT — технический поставщик данных;
- `publisher`: оригинальное СМИ/издатель;
- `author`: автор, если доступен;
- `publishedAt`: дата публикации;
- `originalUrl`: ссылка на оригинал;
- `title` и разрешённый `description`;
- `imageLicense`/`imageAttribution`, если используется стороннее изображение;
- дату получения и срок допустимого хранения данных;
- признак того, разрешено ли сохранять конкретные поля в избранном.

`provider` и `publisher` нельзя объединять в одно поле: Google Play требует
понятно показывать источник статьи, а NewsData.io/GDELT часто являются только
техническими агрегаторами.

На карточке обязательно показывать:

- оригинального издателя или автора;
- дату публикации;
- визуально понятное действие «Читать в источнике».

На детальном экране дополнительно показывать:

- полный URL или домен источника;
- дисклеймер о переходе на сторонний сайт;
- атрибуцию изображения, если она требуется;
- кнопку сообщения о проблеме с материалом/правами через контакт разработчика.

## 6. Что обязательно добавить в приложение для Google Play

Приложение является новостным агрегатором и попадает под News & Magazine policy,
если выбрана соответствующая категория либо слова `news`/«новости» используются
в названии, иконке, developer name или описании. С 27 августа 2025 года такие
приложения обязаны заполнить News and Magazine declaration в Play Console.

### 6.1. Экран «О приложении» / «Источники и лицензии»

Добавить доступный из настроек экран со следующей информацией:

- название и версия приложения;
- имя разработчика/владельца приложения;
- формулировка «независимый агрегатор новостей»;
- указание, что приложение не связано с отображаемыми СМИ и не одобрено ими;
- список NewsData.io и GDELT с кликабельными ссылками;
- атрибуция GDELT;
- ссылки на условия использования провайдеров;
- описание того, что права на статьи и изображения принадлежат их
  правообладателям;
- ссылка на Privacy Policy;
- ссылка на контактную страницу;
- email для вопросов, жалоб и copyright/takedown-запросов;
- ссылка на репозиторий проекта, если он остаётся публичным;
- дата последней проверки условий источников.

Не использовать названия или логотипы СМИ так, чтобы приложение выглядело их
официальным продуктом.

### 6.2. Контактная страница

Google Play требует легко доступную и актуальную контактную информацию для
новостного приложения.

Нужно создать публичный HTTPS URL, например страницу GitHub Pages, содержащую:

- название приложения;
- имя разработчика или legal entity, указанное в Play Console;
- рабочий email или телефон;
- способ отправить жалобу на материал или нарушение авторских прав;
- ссылку на Privacy Policy.

Тот же URL указать:

- в приложении;
- в News and Magazine declaration;
- в Store Listing/контактных данных, где это применимо.

Одной ссылки на профиль в социальной сети недостаточно.

### 6.3. Данные каждой статьи

Для каждой статьи/события UI обязан явно показывать:

- оригинального издателя или автора;
- дату публикации;
- ссылку на оригинальную публикацию;
- технического провайдера там, где это нужно для атрибуции.

Контент должен регулярно обновляться. Для приложений с текущими новостями
Google ожидает материалы не старше 30 дней, а дата публикации должна быть ясно
видна. Ошибки загрузки не должны оставлять приложение с одной статической
демонстрационной лентой на месяцы.

### 6.4. Privacy Policy

До публикации создать публичную Privacy Policy и добавить ссылку на неё в Play
Console и внутри приложения.

Политика должна честно описывать:

- какие данные приложение собирает или не собирает;
- какие данные уходят NewsData.io, GDELT и другим сетевым сервисам;
- передачу поисковых запросов, выбранного языка/региона и технических сетевых
  данных, если она происходит;
- цели обработки;
- сроки хранения локального кэша и избранного;
- наличие или отсутствие аккаунтов, аналитики, рекламы и crash reporting;
- список сторонних сервисов со ссылками на их privacy policies;
- способы защиты данных;
- правила для детей/целевую аудиторию;
- способ задать вопрос или запросить удаление данных, если удаляемые данные
  вообще собираются;
- дату вступления политики в силу и порядок уведомления об изменениях.

Не писать «приложение не собирает данные», пока не проверены все SDK и сетевые
запросы. Перед заполнением декларации составить таблицу всех данных, покидающих
устройство, включая автоматически передаваемые технические данные.

### 6.5. Data Safety

В Play Console заполнить Data Safety на основе фактического поведения release
APK:

- провести аудит всех библиотек и SDK;
- проверить, передаются ли поисковые запросы третьим сторонам;
- проверить аналитику, crash reporting и push-уведомления, если они появятся;
- указать шифрование трафика — все запросы должны идти по HTTPS;
- указать возможность удаления данных, если приложение создаёт аккаунты или
  хранит пользовательские данные на сервере;
- повторно обновлять декларацию при добавлении нового SDK или backend.

Если аккаунтов нет и избранное хранится только локально, это нужно описать
правдиво, но наличие сетевых API всё равно требует проверки определений
`collected`, `shared` и `ephemeral processing` в актуальной форме Play Console.

### 6.6. News and Magazine declaration

В Play Console правдиво указать:

- что приложение является агрегатором сторонних новостей;
- владельца приложения/legal entity;
- тип владельца, например independent/personal developer, если форма предлагает
  такой подходящий вариант;
- основной вид контента;
- NewsData.io и GDELT как поставщиков данных;
- отсутствие собственной редакции, если её действительно нет;
- контактный URL, совпадающий с URL внутри приложения;
- отсутствие монетизации на момент подачи, если форма спрашивает об этом.

Не представлять приложение как самостоятельное СМИ и не приписывать себе
редакционные награды, членство или авторство стороннего контента.

### 6.7. Интеллектуальная собственность

Google Play запрещает приложения, нарушающие copyright и trademarks, и может
запросить доказательство прав на сторонние материалы.

До отправки сохранить:

- PDF/скриншоты актуальных тарифов и условий API с датой;
- ответы поддержки NewsData.io о public display, картинках и кэшировании;
- список всех сторонних изображений и их лицензий;
- исходники собственных placeholder-изображений;
- текст атрибуции GDELT;
- перечень мест UI, где показаны publisher, author и original URL.

Для Store Listing использовать только собственную иконку, собственные
скриншоты интерфейса и лицензированные изображения. Не помещать логотипы СМИ в
иконку или feature graphic.

### 6.8. Остальные обязательные разделы Play Console

Перед релизом также проверить и заполнить:

- App category: `News & Magazines`, если приложение позиционируется как новости;
- Target audience and content: не выбирать детей целевой аудиторией без полной
  готовности соблюдать Families Policy;
- Content rating: учитывать, что реальные новости могут содержать насилие,
  войну, преступления и другие чувствительные темы;
- Ads declaration: указать отсутствие рекламы, пока её действительно нет;
- App access: если позже появится авторизация, предоставить Google тестовый
  доступ;
- Content declarations и прочие карточки App content, показанные для аккаунта;
- Store Listing: ясно назвать приложение независимым агрегатором и описать
  источники;
- актуальный target API level к дате публикации;
- тестирование release AAB, а не только debug APK;
- рабочие ссылки на Privacy Policy, контакты и оригинальные статьи;
- отсутствие секретов и debug endpoints в release AAB.

Правила Google Play применяются не только к собственному UI, но и к контенту,
который приложение отображает или на который ссылается. Следует предусмотреть
фильтрацию явно запрещённого контента и рабочий канал для жалоб.

## 7. Чек-лист перед каждым релизом

- [ ] News API отсутствует среди release-источников.
- [ ] Release не содержит ключ News API и не обращается к `newsapi.org`.
- [ ] Повторно проверены условия NewsData.io и GDELT; обновлена дата документа.
- [ ] Есть актуальное подтверждение NewsData.io для картинок и кэширования.
- [ ] GDELT-карточки не используют нелицензированные изображения издателей.
- [ ] На каждой карточке видны publisher/author и дата.
- [ ] Каждая статья открывает оригинальный URL.
- [ ] Добавлена кликабельная атрибуция GDELT.
- [ ] Экран «Источники и лицензии» заполнен и доступен из настроек.
- [ ] Контактный HTTPS URL работает и совпадает с декларацией Play Console.
- [ ] Privacy Policy соответствует фактическому поведению release APK.
