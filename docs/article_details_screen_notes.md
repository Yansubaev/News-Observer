# Экран подробностей статьи

Актуальность заметки: **15 августа 2026 года**.

Документ фиксирует согласованный состав экрана подробной информации о статье,
требования к атрибуции и переходу на сайт издателя, а также рекомендуемую
навигацию и UI/UX. Общие лицензионные требования и подготовка к Google Play
описаны в
[news_sources_licensing_and_google_play.md](news_sources_licensing_and_google_play.md).

## 1. Назначение экрана

Экран является **подробным предпросмотром**, а не экраном чтения полного текста
статьи.

Приложение показывает:

- заголовок;
- краткое описание, полученное через API;
- оригинального издателя;
- автора, если он предоставлен;
- дату публикации;
- разрешённое изображение или собственный placeholder;
- технического поставщика метаданных;
- кнопку перехода к оригинальной публикации.

Полный материал пользователь читает на сайте оригинального издателя. Такая
модель не создаёт локальную копию статьи, лучше показывает источник и снижает
риски нарушения прав на полный текст.

## 2. Что обязательно показать

На экране должны присутствовать:

- **оригинальный издатель** (`publisher`), например BBC News или Reuters;
- **автор**, если API вернул это поле;
- **полная дата и время публикации** в локальном формате;
- **заголовок** без обрезки по количеству строк;
- **полное краткое описание**, которое вернул API;
- **оригинальный домен или URL**;
- понятная кнопка перехода к оригинальной публикации;
- **технический провайдер**: NewsData.io или GDELT;
- атрибуция изображения, если этого требует его лицензия;
- атрибуция GDELT для материалов, полученных через GDELT.

Если автор отсутствует, строка автора скрывается. Издатель при этом должен быть
указан всегда. Если невозможно определить издателя или оригинальный URL, такой
элемент не следует показывать в release-ленте.

Google Play требует, чтобы новостный агрегатор явно показывал источник каждой
статьи, включая оригинального издателя или автора. Для текущих новостей также
должна быть ясно указана дата публикации.

## 3. Издатель и технический провайдер

Понятия нельзя объединять:

```text
publisher — организация, опубликовавшая статью;
provider  — API/сервис, через который приложение получило метаданные.
```

Примеры отображения:

```text
BBC News
Данные предоставлены через NewsData.io
```

```text
Reuters
Метаданные события: GDELT Project
```

Существующее поле `Article.sourceName` не покрывает оба значения. Перед
подключением новых API domain-модель следует расширить, например:

```kotlin
enum class NewsProvider {
    NEWS_DATA,
    GDELT,
    NEWS_API,
}

data class Article(
    // Остальные поля...
    val provider: NewsProvider,
    val publisherName: String,
    val publisherDomain: String?,
    val author: String?,
)
```

`NEWS_API` доступен только в debug. Это ограничение сборки описано в общем
compliance-документе.

## 4. Атрибуция провайдеров

### NewsData.io

На подробном экране достаточно небольшой строки:

> Данные предоставлены через NewsData.io

Оригинальным источником всё равно показывается издатель статьи. NewsData.io не
должен отображаться как автор или издатель.

До письменного подтверждения NewsData.io необходимо считать отдельно не
подтверждёнными:

- публичное отображение `image_url`;
- бессрочное хранение заголовка и описания в избранном;
- формулировку обязательной атрибуции, если провайдер её требует.

### GDELT

Для каждого GDELT-элемента показывать:

> Метаданные предоставлены GDELT Project

`GDELT Project` должен быть кликабельной ссылкой на
`https://www.gdeltproject.org/`.

Ссылка может находиться в блоке информации об источнике. Общая атрибуция также
должна присутствовать на экране «Источники и лицензии».

## 5. Изображения

### NewsData.io

Изображение из ответа API можно использовать в release только после
подтверждения, что текущие условия тарифа разрешают его публичное отображение в
стороннем Android-приложении.

До подтверждения использовать собственный placeholder.

### GDELT

В release запрещено использовать поля `socialimage`, `sharingimage` и другие
URL изображений, которые GDELT обнаружил на сайте издателя, если у конкретного
файла нет явной лицензии.

Для GDELT использовать:

- отсутствие hero image;
- собственный placeholder по категории;
- собственную иллюстрацию;
- проверенное изображение CC0/public domain;
- Wikimedia Commons с проверенной лицензией и корректной атрибуцией.

Hotlink не заменяет лицензию. Нельзя скачивать, проксировать или кэшировать
изображение издателя только потому, что его URL вернулся в GDELT.

### Accessibility изображения

Если API не предоставляет настоящее текстовое описание изображения, не нужно
использовать заголовок статьи как `contentDescription`: TalkBack дважды прочитает
один и тот же текст. Такое изображение считать декоративным:

```kotlin
contentDescription = null
```

Если изображение несёт уникальную смысловую информацию и доступно корректное
описание, использовать это описание.

## 6. Предлагаемый UI

```text
┌──────────────────────────────────────┐
│ ←  Подробности              ♡   ↗    │
├──────────────────────────────────────┤
│                                      │
│       лицензированное изображение    │
│       или собственный placeholder    │
│                                      │
├──────────────────────────────────────┤
│ BBC News                             │
│ 15 августа 2026, 14:30               │
│ Автор: John Smith                    │
│                                      │
│ Крупный заголовок статьи, который    │
│ может занимать несколько строк       │
│                                      │
│ Полное краткое описание, полученное  │
│ через API. На этом экране оно не     │
│ ограничивается тремя строками.       │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ Оригинальная публикация          │ │
│ │ bbc.com                          │ │
│ │ Данные: NewsData.io              │ │
│ └──────────────────────────────────┘ │
│                                      │
│ [ Читать на сайте BBC News      ↗ ]  │
│                                      │
│ Сообщить о проблеме                  │
└──────────────────────────────────────┘
```

### Порядок блоков

1. Верхняя панель навигации.
2. Изображение или placeholder.
3. Издатель и дата.
4. Заголовок.
5. Автор, если доступен.
6. Краткое описание.
7. Блок оригинальной публикации и провайдера.
8. Основная кнопка перехода.
9. Необязательная ссылка «Сообщить о проблеме».

Не нужно искусственно заполнять свободное место дополнительным текстом. Если у
статьи нет описания или изображения, экран может быть короче.

### Верхняя панель

В `TopAppBar` разместить:

- кнопку «Назад»;
- кнопку избранного;
- кнопку «Поделиться».

При отправке через Android Sharesheet передавать оригинальный URL статьи, а не
внутренний route приложения.

На подробном экране нижнюю навигацию Home/Search/Favorites лучше скрыть. Экран
открывается поверх текущего раздела и возвращает пользователя назад в прежнее
место списка.

## 7. Кнопка оригинальной публикации

Предпочтительный текст:

> Читать на сайте {publisherName}

Например:

> Читать на сайте BBC News

Допустимые запасные варианты:

- «Открыть оригинал»;
- «Перейти к полной статье».

«Читать в источнике» понятно, но звучит более технически. Название издателя в
кнопке заранее объясняет пользователю, куда он перейдёт.

Кнопка должна:

- быть основной и полноширинной;
- иметь иконку внешней ссылки;
- иметь touch target не менее 48 dp;
- быть доступной с TalkBack;
- открывать только проверенный `http`/`https` URL;
- показывать понятную ошибку, если URL отсутствует или некорректен.

Под кнопкой можно добавить вспомогательный текст:

> Откроется на сайте оригинального издателя

## 8. Custom Tabs вместо WebView

Принятое решение: для оригинальной публикации использовать **Android Custom
Tabs** с fallback на обычный браузер через `ACTION_VIEW`.

Причины:

- страница принадлежит стороннему издателю, а не приложению;
- пользователь видит настоящий домен;
- используются cookies, авторизация и paywall браузера;
- браузер управляет Safe Browsing и учётными данными;
- корректнее работают переходы, загрузки и современные возможности сайта;
- приложение не обязано самостоятельно управлять cookies и безопасностью
  WebView;
- сохраняется визуальный контекст приложения и нормальная кнопка «Назад».

Алгоритм:

```text
URL не http/https         → не открывать, показать ошибку;
Custom Tabs поддерживается → открыть Custom Tab;
иначе                     → открыть ACTION_VIEW в браузере;
браузер отсутствует       → показать понятное сообщение.
```

WebView использовать только если позднее появится собственный веб-контент,
которым управляет приложение. Для страниц сторонних СМИ WebView создаёт лишние
риски безопасности, приватности, cookies и совместимости.

## 9. Состояния неполных данных

- Нет изображения — скрыть hero-блок или показать собственный placeholder.
- Нет автора — скрыть строку автора без пустого места.
- Нет описания — сразу показать блок источника и кнопку перехода.
- Нет даты — показать «Дата публикации не указана», но такие элементы желательно
  отфильтровывать до попадания в release-ленту.
- Нет оригинального URL — не показывать элемент в release либо отключить кнопку
  с понятным объяснением.
- Длинный заголовок — показывать полностью.
- Длинное описание — показывать полностью в прокручиваемом контенте.
- Ошибка открытия URL — Snackbar с нейтральным сообщением и возможностью
  повторить.
- Ошибка загрузки изображения — placeholder без бесконечного progress state.

На экране нельзя показывать выдуманные данные. Не рассчитывать `reading time`,
если у приложения нет законно доступного полного текста.

## 10. Что не показывать

- Полный текст статьи без явно подтверждённых прав.
- HTML, полученный скрейпингом оригинальной страницы.
- Автоматический перевод статьи без отдельного анализа прав.
- Логотип издателя без разрешения.
- Изображение GDELT с сайта издателя без лицензии.
- Поле `content` только потому, что оно существует в текущей domain-модели.
- Кнопку скачивания статьи.
- Формулировки, создающие впечатление, что Observer является автором или
  официальным приложением издателя.

## 11. Навигация и загрузка данных

В `ArticleCard` добавить независимые callbacks:

```kotlin
onArticleClick: (Article) -> Unit
onFavoriteClick: (Article) -> Unit
```

Нажатие на кнопку избранного не должно вызывать `onArticleClick`.

Не передавать весь объект `Article` и сырой URL в route. Использовать стабильный
идентификатор вместе с провайдером:

```text
article/{provider}/{articleId}
```

Экран загружает объект из Room или репозитория по составному ключу
`provider + articleId`. Это позволяет:

- открывать один экран из Home, Search и Favorites;
- корректно восстанавливаться после пересоздания процесса;
- не упираться в экранирование длинных URL;
- различать одинаковые ID разных провайдеров.

Если API не предоставляет стабильный ID, нужно хранить собственный стабильный
ключ, например hash нормализованного original URL вместе с provider. URL при
этом остаётся обычным полем, а не navigation argument.

### Предлагаемая структура presentation-слоя

```text
presentation/article/
├── ArticleDetailsScreen.kt
├── ArticleDetailsUiState.kt
└── ArticleDetailsViewModel.kt
```

Экран использует собственный `Scaffold`:

- `TopAppBar` с навигацией и действиями;
- `LazyColumn` или прокручиваемый `Column`;
- основная кнопка в конце контента либо в `bottomBar`;
- состояния loading/content/error/not found.

## 12. Нефункциональные требования

- Все пользовательские строки вынести в `strings.xml`.
- Поддержать светлую и тёмную тему Material 3.
- Проверить большие системные размеры шрифта.
- Не задавать фиксированную высоту текстовым блокам.
- Учесть системные insets и edge-to-edge.
- Обеспечить контраст текста и кнопок.
- Добавить Compose Preview минимум для:
  - полной статьи;
  - статьи без изображения;
  - статьи без автора и описания;
  - GDELT-статьи с placeholder и атрибуцией;
  - тёмной темы.
- Добавить UI-тесты на переход, кнопку назад, избранное и внешний URL.
- Валидировать URL перед созданием Intent.
- Не логировать полный URL, если он содержит чувствительные query parameters.

## 13. Чек-лист реализации

- [ ] В domain-модели разделены `provider` и `publisher`.
- [ ] Для статьи есть стабильный ID в пределах provider.
- [ ] `ArticleCard` имеет отдельный `onArticleClick`.
- [ ] Добавлен route `article/{provider}/{articleId}`.
- [ ] Экран открывается из Home, Search и Favorites.
- [ ] На экране видны издатель и абсолютная дата публикации.
- [ ] Автор показывается только при наличии.
- [ ] Заголовок и описание не обрезаются.
- [ ] GDELT имеет кликабельную атрибуцию.
- [ ] GDELT не использует нелицензированные изображения издателей.
- [ ] NewsData.io image включается только после подтверждения прав.
- [ ] Основная кнопка содержит имя издателя и иконку внешней ссылки.
- [ ] Внешняя страница открывается через Custom Tabs.
- [ ] Есть fallback на `ACTION_VIEW`.
- [ ] Разрешены только `http`/`https` URL.
- [ ] Share передаёт оригинальный URL.
- [ ] Кнопка избранного не запускает навигацию.
- [ ] На detail-экране скрыта нижняя навигация.
- [ ] Обработаны отсутствующие image/author/description/date/URL.
- [ ] Добавлены accessibility descriptions и проверены touch targets.
- [ ] Добавлены previews и UI-тесты.
