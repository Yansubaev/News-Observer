# Экран настроек — заметки на будущее

Черновик содержания экрана Settings. Порядок ниже — рекомендуемый (по UX-логике: сначала контент, потом хранение данных, потом уведомления, "О приложении" — всегда последним).

## 1. Выбор источников новостей

Принятое решение: в release доступны NewsData.io и GDELT, а уже реализованный
News API остаётся только в debug-сборке. Лицензионные ограничения, правила
отображения контента и Google Play checklist описаны в
[отдельном документе](news_sources_licensing_and_google_play.md).

**Внедрение:**
- Расширить существующий `Source` значениями `NEWS_DATA` и `GDELT`.
- Доступность `NEWS_API` определять вариантом сборки; в release его не должно
  быть в списке настроек и не должно быть рабочего ключа/клиента.
- В `SettingRepository` хранить `Set<String>` включённых источников в DataStore
  (по умолчанию — все доступные для текущей сборки).
- Нельзя позволять выключить последний активный release-источник.
- Сделать отдельные DTO/API/мапперы каждого провайдера и приводить ответы к
  общей domain-модели `Article`; не переиспользовать News API `ArticleDto` для
  несовместимых JSON-схем.
- В общей модели различать технического провайдера (`provider`) и оригинального
  издателя (`publisher`).
- Paging, кэш и избранное должны учитывать источник и его правила хранения.

## 2. Смена языка статей

Выбор языка, на котором приходят статьи (NewsAPI поддерживает параметр `language` в поиске и, по всей видимости, только в `everything`, не в `top-headlines`).

**Внедрение:**
- `NewsApi.searchNews` уже принимает `language` (по умолчанию `"en"`) — просто не прокинут из настроек. В `top-headlines`/`getHeadlines` языка нет вообще (NewsAPI регулирует язык через `country`), это стоит учитывать при проектировании UI, чтобы не обещать то, чего API не даёт для главного экрана.
- В `SettingRepository` добавить `languagePreference` (DataStore), по умолчанию — язык системы (`Locale.getDefault().language`), если он входит в список поддерживаемых NewsAPI языков, иначе — `"en"`.
- Список языков у NewsAPI фиксированный (ar, de, en, es, fr, he, it, nl, no, pt, ru, sv, ud, zh) — просто enum/список констант, без сети.

## 3. Смена региона (страны)

Регион для `top-headlines` (`country`, например `"us"`, `"ru"`).

**Внедрение:**
- Уже есть баг-несостыковка: `HomeViewModel` хардкодит `country = "us"` напрямую, а `SettingRepository.getCountryPreference()` существует и используется только в `ArticleRemoteMediator`. При реализации этого пункта — свести оба места на один источник правды (`SettingRepository`).
- По умолчанию — регион системы (`Locale.getDefault().country`), с ручным переопределением в UI.
- Список поддерживаемых стран у NewsAPI тоже фиксированный и небольшой — так же можно захардкодить как константы/enum.
- Заодно, раз уже трогаем этот кусок `SettingRepository`, по такой же схеме позже легко добавить категорию/сортировку по умолчанию для главного экрана и поиска (`Category` enum и `sortBy` уже готовы в коде) — но это не обязательно делать сейчас.

## 4. Кнопка «Очистить кэш» (не трогая избранное)

Простой пункт в разделе про хранение данных.

**Внедрение:**
- В `ArticleDao` уже есть готовые запросы: `deleteNonFavorites`, `deleteNonFavoritesByPage`, `deleteNonFavoritesByCategory` — нужно только дёрнуть один из них (скорее всего `deleteNonFavorites`) из нового `SettingsViewModel`.
- После очистки желательно сбросить `lastSyncTime` в `SettingRepository`, чтобы `ArticleRemoteMediator` сразу перезапросил свежие данные, а не ждал `syncInterval`.
- Неплохо показать диалог подтверждения и/или тост "Кэш очищен".

## 5. О приложении

Стандартный пункт: версия приложения, возможно ссылка на репозиторий/лицензии, обязательный атрибьюшн источника данных.

**Внедрение:**
- Версию можно брать из `BuildConfig.VERSION_NAME` — не хардкодить строкой.
- Добавить отдельный экран «Источники и лицензии», контактный URL, Privacy
  Policy, атрибуцию GDELT и сведения об оригинальных издателях согласно
  [release/compliance checklist](news_sources_licensing_and_google_play.md).
- News API используется только в debug и не должен упоминаться как доступный
  источник release-версии.
- Ключи уже читаются из `local.properties`/environment, что защищает их от
  случайного коммита, но значения `BuildConfig` всё равно извлекаются из APK.
  Для release-ключа NewsData.io следует рассмотреть backend/proxy.

## 6. Уведомления о новых статьях

Самый тяжёлый пункт — под него сейчас нет вообще никакой инфраструктуры (ни WorkManager, ни notification channel, ни permission).

**Внедрение (с нуля):**
- Добавить зависимость `androidx.work:work-runtime-ktx`, разрешение `POST_NOTIFICATIONS` в манифест (Android 13+ требует runtime-запрос).
- `PeriodicWorkRequest` с интервалом (можно переиспользовать/расширить существующий `syncInterval` из `SettingRepository`) — воркер дёргает тот же путь получения новых статей, что и `ArticleRemoteMediator`, и сравнивает с уже сохранёнными в Room, чтобы понять, есть ли новые.
- На экране Settings — просто свитч вкл/выкл + (опционально) выбор частоты проверки; сам permission-флоу (запрос POST_NOTIFICATIONS) обрабатывать на уровне включения свитча.
- Так как это самый крупный и рискованный пункт (новая зависимость, новый permission, фоновая работа, батарея), имеет смысл делать его последним и отдельным этапом, когда остальные пункты уже стабильны.

## Где разместить экран

- В навигации уже есть таб `Screen.Profile` без реального экрана (`AppNavHost.kt` не регистрирует под него composable) — логичное место, чтобы либо переименовать в Settings, либо повесить туда новый `presentation/settings/SettingsScreen.kt` + `SettingsViewModel.kt` по образцу существующих экранов (Hilt `@HiltViewModel`, паттерн как в `FavoritesViewModel`).
